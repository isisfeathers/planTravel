# Atrip 非工程團隊分工與雲端硬碟交件指南 (Non-Tech Team Collaboration & Git Gatekeeper Guide)

* **適用情境**：團隊成員非工程背景、大量仰賴 AI 工具（ChatGPT / Claude / Cursor / Copilot）進行開發。
* **核心策略**：**「單一守門人架構 (Single Gatekeeper Model)」** —— 成員不直接操作 Git，透過雲端硬碟獨立目錄交件，統一由主事者（你）進行驗收、合併與 Git 版控。
* **核心效益**：100% 避免 Git Merge 衝突、Detached HEAD、強制覆蓋等災難，讓成員將 100% 精力專注於向 AI 提問與功能交付。

### 你的 Git 守門人操作步驟：
1. **下載成品**：將成員上傳至雲端硬碟的檔案抓回本地對應目錄。
2. **本機快速檢查 (Sanity Check)**：
   * 後端 SQL：在 Supabase 本地或測試環境執行一次，確認無 Syntax Error。
   * 前端 Code：執行 `npm run build` 或 `npm test`，確認無 TypeScript 型別報錯。
   * 機票 Code：執行測試查詢，確認能產出 `FlightOfferItem[]`。
3. **優雅提交 Git (Clear Commits)**：
   ```bash
   # 例如整合後端成果
   git add supabase/
   git commit -m "feat(backend): deploy initial schema and prompt templates (TRACK2-01, TRACK2-02)"

   # 例如整合機票模組
   git add services/flight-service/
   git commit -m "feat(flight): implement search orchestrator and amadeus adapter (TRACK3-02)"

   # 例如整合前端標籤精靈
   git add src/components/ChipWizard/
   git commit -m "feat(frontend): implement dual-layer chip selector logic (TRACK1-03)"

   # 推送上雲端
   git push origin main
   ```

這樣做，成員**完全不會碰到 Git 衝突**，你也能**完全掌控每一行進入 Git 主分支的程式碼品質**，專案推進將會是最穩健、最乾淨的狀態！
